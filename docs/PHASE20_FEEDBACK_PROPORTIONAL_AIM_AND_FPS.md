# Phase 20: 行き過ぎ防止＋実測FPS表示（2026-10-29）

## 実機のフィードバックから直した点

- 横方向の**符号は変更しない**。現実で左へ移動した時に追従することは実機で確認済み。
- 従来の「検出1フレームごとに画面のズレを角度へ足す」処理は、GPUのFPSが高いほど角度が積み上がる。これを廃止して、**新鮮なESP32内部角度 + 現在の顔位置の比例補正**から次の位置を計算する。
- 横・縦ともに比例ゲインと中心デッドゾーンを持たせ、1回のESP32角度に対する補正は最大±0.6°。Piが生成する指令値の速度制限はデフォルト**2°/秒**（引数で小さくできる）。角度コマンドは最大20 Hz。GPUのFPSを上げても角速度上限は上がらない。
- 画面の位置平滑化は「1フレームにつき40%」から、実際の経過時間を使う時定数0.08秒へ変更。30 FPSでも60 FPSでもほぼ同じ応答で、遅延による追い越しを減らす。
- 首Yawは引き続き±3°。Pitchは引き続き明示的な物理キャリブレーションと上下範囲フラグがない限り0°。
- ESP32の内部角度が古い・不正な場合は、新しい首目標を作らない。内部角度はPWM角度の**ソフトウェア上の推定値**で、実軸にエンコーダが付いているわけではない。
- 人物YOLO＋Poseの鼻座標、検出がなければ肩中央や人物枠上部を利用。**生体的な顔認証ではない**。
- 本体旋回は従来の追加フラグ、頭部限界到達、テレメトリ、IDLE、安定確認が必要。安全ゲートやESP32ファームは変更なし。

## カメラ・首のみ低速テスト

初回は本体旋回を有効にしない。固定した機体、ニュートラル・上下限界・外部の物理電源遮断が確認できてから行う。左右方向の反転オプションは**付けない**。

```bash
python3 experiments/pc_gpu/pi_real_head_integration.py \
  --serial-port /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0 \
  --servo-power-on --pc-host 127.0.0.1 \
  --enable-head-test \
  --head-speed-deg-per-second 1.5 \
  --camera-width 640 --camera-height 480 --camera-fps 30 \
  --bench-secured --neutral-calibrated --physical-cutoff-tested
```

首の上下もキャリブレーション済みなら、**実機で干渉のない範囲**を確認してから次の引数を加える（下記は±2°まで実測で安全が確認できた機体だけの例）。

```text
--pitch-calibrated --pitch-min-deg -2 --pitch-max-deg 2
```

`--head-speed-deg-per-second 1.5`は初回のさらに低速な検証値。Piのデフォルトは2.0°/秒。移動幅が大きい・左右上下で追い越す場合はAUTOを止めて再度観察する。セーフティのため自動で角度限界を広げないこと。

## カメラFPSについて

- `--camera-fps 30`は**カメラドライバへの希望値**。USBカメラ、PiのJPEG圧縮、SSH経路、PCのGPU推論の往復待ちがあるため、実際に30FPS出る保証はない。
- 操作画面の「カメラ・中心合わせ」ヘッダに**実測 FPS**と**GPU推論 ms**を表示する。FPSはPiが結果を受け取れた周期の近似値。
- Piは各フレームをJPEG送信し、PCのYOLO結果が返るのを待って次を送る方式。GPUを速くしてもUSBカメラやネットワークが律速ならFPSは上がらない。
- カメラ映像内の`SCREEN LEFT/RIGHT`、`dx/dy`、`YAW/PITCH`を確認し、**顔が中央に近づくにつれて首指令が減り、停止するか**を観察する。
- 実測FPSとGPU推論msが不明なまま画像サイズを小さくしない（顔位置・ジェスチャーの精度が下がり得る）。必要なら次の最適化を検討する。
