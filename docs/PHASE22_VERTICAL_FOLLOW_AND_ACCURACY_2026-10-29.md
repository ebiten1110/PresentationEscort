# 2026-10-29 実機ログ: 上下追従と人物ロック精度

## 観測された事実

`PresentationEscort-diagnostics (2).zip`（2026-10-29 15:07 JST）には600件の推論記録がある。600件のうち269件がAUTO、330件が人物TRACKING、263件が一時的または完全なロスト、566件に人物検出がある。画像取得は640x480で約5.6 FPS、平均GPU推論は約35.9ms、平均往復RTTは約113.5ms。実機ESP32が報告するPitchは-2.0°から+2.0°まで変化した。

上下追従は既に実行されていた。未実装ではなく、ユーザーが検証した起動値は**Pitch±2°** と **首速度0.5°/秒** であり、上下移動を認識しづらい。実験画像には顔の狙点が画像中央から150px以上離れた例があり、±2°では補正しきれない。**機械可動域の安全が実証されるまで±2°を広げない。**

## 新しい制御オプション

- `--pitch-speed-deg-per-second 1.5`: 上下だけ最高1.5°/秒に設定。左右の`--head-speed-deg-per-second 0.5`を保持できる。いずれもESP32からの最新角度に対する補正、1コマンド最大0.6°、角度上限、送信間隔のガードを維持する。
- `--reverse-vertical-direction`: 上下の実機方向が画面の期待と逆だと確認した場合のみ指定。**実機で上下方向を確認するまで付けない。**
- オペレーター画面の「追従判定」に上下目標角度、ESP32報告値、上下速度上限、上下限到達、顔位置の信頼性による上下保持を表示。診断ZIPにも同じ項目を記録する。
- 上下未校正時は従来通りPitch 0°、上下可動範囲は変更せず、ボディ移動許可も変更しない。

既存の展示用起動コマンドで、事前校正済み±2°であることを再確認したうえで、次を追加する：

```shell
--head-speed-deg-per-second 0.5 --pitch-speed-deg-per-second 1.5 \
--pitch-calibrated --pitch-min-deg -2 --pitch-max-deg 2
```

**注意:** サーボが物理的に前述の角度を動いたと断定できるのは角度検出器（軸エンコーダ）ではない。診断値はESP32内部の目標・補間角度であり、機械的追従や正しい方向は人の目で検証が必要。

## 精度改善の優先順位（未実装の提案）

1. **視覚ロックの持続性:** 600件中「TRACKING」330件に対して、ロスト263件。人物が写っているのにロックが外れたケースを人物ID、bbox連続性、顔・肩のキーポイント、少しの遮蔽許容を併用して改善する。別人への誤切替を避け、確度が低い間は首・体を止める。
2. **レイテンシー:** GPU平均35.9msでも実効約5.6FPS。Piで最新フレームのみを送って古いフレームを捨てるキュー、USBカメラの実際のモード/FourCC/MJPEG/露光、JPEG圧縮・SSH転送・PC推論の時間を段階計測。`--camera-fps 30`は要求値であり測定値ではない。
3. **上下の見え方:** 顔が上端で切れているときは鼻位置に依存し過ぎず、肩・上半身を補助指標にする。顔座標が不安定なときは速度上限を保ちながら補正を弱め、ロックが切れたら即停止する。
4. **過補正:** 画像誤差とESP32内部角度の時系列を同時にログ記録し、角度速度・画像遅延・デッドゾーンを実測で合わせる。GPU FPSだけ上げてもサーボ許可範囲や同期誤差は解決しない。

## 推奨フロー（設計案、未実装）

`待機（黄）→両手挙げを4フレーム確認→対象ロック→顔/肩狙点の安定化→首Yaw/Pitch追従（白）→首Yaw限界かつ画面端でのみ短い本体旋回→連続3フレーム同一人物を確認して追従継続→失敗ならSAFE（赤/黄は待機許可に応じる）→新しい両手挙げで再開`。

- **「両手挙げ＝人物の登録」** と **「顔中心の幾何学的校正」** は別機能。現状の両手挙げは追従対象の指定・開始であり、サーボ原点/角度の自動キャリブレーションではない。
- 見失い方向が本当に画面端へ抜けた直後でない限り、方向予測だけで本体を旋回しない。
- 同一人物の確認ができない場合、別人を勝手に追跡しない。緊急停止や通信断からの再ARMは常に明示操作が必要。
- 実機の上下許可範囲拡張、本体旋回、自動原点補正は別途物理校正が必要。今回のコード変更はそれらの許可を追加しない。
