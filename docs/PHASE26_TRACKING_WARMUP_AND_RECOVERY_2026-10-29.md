# Phase 26 — 首振りの暴走防止と短い見失いからの自動復帰 (2026-10-29)

## 診断 ZIP (6) による再現

- 600フレーム中 TRACKING は204、LOSTは355、TEMPORARILY_LOSTは27。AUTOは148フレーム。
- 首Yawフィードバックが可動範囲端の±3°になっていたのは117フレーム。人物を一時的に見失った後、±3°のまま再キャリブレーションするケースが多数。
- seq704〜713では、顔が画像x=402→442pxへ動く間、首Yawは-3°のまま。別の旋回提案まで首が端に固定されていた。
- 実効9.0FPS（前回ZIP5は7.1FPS）、平均GPU推論30.4ms、Pi推論往復70.3ms。FPS改善のみで首振り発散は解決しない。

## 修正（PiのPythonのみ・ESP32書換え不要）

1. 首Yawの制御範囲: `--distance-adaptive-head`有効時、従来の近距離±3°/遠距離±1.1°を近距離±1.5°/遠距離±0.75°に縮小。画像中央±8%の顔ぶれは首を振らず、さらに大きな横ズレはESP32本体旋回へ分担。
2. 新たなロック・再認識の初期動作: SAFE中は首の指令位置を積み増さず、ESP32から届いた実角度（ファームウェアの目標角度フィードバック）をそのまま保持。AUTOに入った直後は3フレーム首と本体を動かさず様子を見る。以前のロックでYawが-3°でも、画像中央の顔を見つけた瞬間に0°へ跳ね戻さない。
3. 短い見失いの再キャリブレーション: `--auto-recalibrate-brief-loss`有効時、ESP32が前の旋回を実行中でも、新しい首/脚指令を送らずに最大1.5秒の自動再認識を許容。連続3フレームで同じ一意な候補を認識した場合のみ既存AUTOを継続（STOP/ESTOP後は自動ARMしない）。
4. 本人を完全に見失い、1.5秒を超えた場合や複数人が曖昧な場合は、顔だけでは本人認証できないため自動ARMしない。この状態では黄色の待機モードで両手挙げから再スタート。

## 動作確認 (3ステップ)

1. Pi: `cd ~/PresentationEscort-demo && git pull --ff-only origin feature/pc-gpu-follow-2026-10-28`。 `git rev-parse --short HEAD`で最新版を確認。
2. これまでのPi起動コマンドをそのまま使用。 `--distance-adaptive-head --auto-recalibrate-brief-loss --preview-every-n-frames 3`を含める。ESP32のファームウェア変更なし。
3. 両手挙げ→カメラ中央で静止→少し左右へ移動→大きく移動→短い遮蔽→再び顔を見せる。首の最大角・首の行き過ぎ・AUTO維持・本体旋回方向をまとめて確認。実機の改善を保証するものではないので診断ZIPで比較する。
