# 2026-10-19 PC GPU / Pi 実測ログと安全対策

## 実測
Raspberry Pi 3 A+ (320x240, JPEG品質60) → PC (RTX 4060/CUDA) → Pi。
- 合計121行の結果：人物座標89回、NO_PERSON30回、STALE2回
- GPU推論 infer 中央値50.5ms（89回）
- カメラ取得・JPEG・送受信・GPU推論込み rtt 中央値158.5ms（121回）
- rtt 90パーセンタイル付近231.8ms
- 初回rtt1440.3ms、一時的に571.2msの処理遅延あり
- 左x49 → 中央付近x151 → 右x269 の座標とV8.8.3符号変換を確認
- 横移動中x49→x217への単発の位置飛び、ロストが発生
- 検出BBox高さ239〜240pxが多く、画面内で身体が切れている可能性。上下や距離は未校正

## 実装
PC側にperson_tracker.pyを追加。
- 前回のBBoxとの中心位置と大きさを比較し、連続性のある候補を選択
- 急に離れた検出／サイズが不釣り合いな検出は不採用
- 不一致時は即found=False、古いBBoxを返さない
- 5フレーム連続で不一致ならロック解除。次フレームで再取得
- クライアント接続ごとに対象トラッカーを初期化
- 対象連続性テスト10項目を追加

**制限**：人物認証/ReIDではない。5フレーム以上ロストした後は別人へ乗り換える可能性がある。モーター実動作前に安全停止と再追従許可を実装する。

## 次に行うこと
1. PC・Piでgit pull --ff-only
2. PCサーバーをCtrl+Cで停止し再起動
3. Piでpi_tracking_dry_run.pyを再実行。通常歩行／横切り／遮蔽を検証
4. 誤対象選択・RTT・ロストを再計測
